# 两个真实项目的 Skill 验收

日期：2026-10-11。先验收未修改的 2.1.0 Skill，再实现来源核验和分层导航，最后用 2.2.0 复查同一批真实项目数据。

这里的完整验收指本次约定的**静态建模、源码事实复核和离线阅读器交互**，不包含运行两个项目的业务服务。没有调用真实模型、数据库、付费服务，也没有修改这两个项目。

## 方法

- 将完整 Skill 复制到仓库外，独立 Agent 仅凭 Skill 规则和入口建模、生成；生成不使用本仓库 src、原型或根 node_modules。
- 另一位审阅者对照真实源码核对各项目关键事实，包括失败条件和规划边界。检查存在的引用、有效行号和 SHA-256；这些机械检查不能代替语义复核。
- 用 Chromium 在 offline / file:// 下操作生成的 HTML，记录状态、失败、修正与截图。浏览器自动化驱动使用现有 Playwright，生成本身不需要它。
- 保留基线输出，再把新功能应用到独立 enhanced 输出；真实项目的数据、摘要和截图均不进入 Skill 发布包。

本地完整证据保存于 `artifacts/acceptance/2026-10-11/baseline/` 和 `enhanced/`。artifacts 被 Git 忽略；复跑脚本会取当前工作副本，不能恢复历史源码快照。

### 事实复核与修正

**CiteRAG**：核对前端文字 auto / 可选 Agent 路由，默认 KB adapter 的缓冲与支持核验，保存后 SSE delta，原文来源复核，聊天上下文与 KB 证据的边界，提交锁与 revision/workspace 守卫。修正错误的依赖行号、维护开始递增 revision 的说明；把提供商失败与断线取消拆为独立场景。

**Iteroom**：核对显式启动和 202 受理，Key 校验先于 snapshot/claim，已有 snapshot 校验后复用，唯一只读工具，预算登记先于请求，取消/超时/孤儿恢复，以及 v1 实际接受与 v2 纯契约的边界。为主场景补“首次固定且校验通过”的前提，把输入拒绝、缺 Key、坏快照、预算耗尽、取消、超时和孤儿恢复拆为独立场景。

两份初稿都曾把互斥失败放到一条演示线上，因此新版规则明确要求每个场景只表达一条条件一致的路径。

### 漂移与脚本失败

CiteRAG 基线期间发生外部 README 变化和暂存状态变化，其余 26 个引用文件摘要一致；重新阅读 README、修正行号和摘要后重生成，保留漂移前记录。新版首次复查时 HEAD 变为 `6b50f611d29b99b2553340cee3d078bff5abf36c`，全部 27 个引用文件摘要仍一致。之后 runtime.py 与 frontend README 又发生外部内容变化：只读审阅差异，确认图中 KB 查询、缓冲与上下文证据边界仍成立，核对原引用行文本并修正 21 处结构化引用的行号，再固定新摘要。enhanced 报告保留修改前快照、源码差异审阅和重新严格检查；源树始终只读，不声称全程未变。

验收脚本也出现过 Windows 文件通配/路径错误、Node ESM 路径错误、根 shell 归属漏算、重复 toggle 导致闭合、控件焦点抑制快捷键等失败。分别修正脚本与断言，保留原始失败；超时或中止运行不计入通过项。

### 视觉结果

实际查看了总览、AnswerService/Host 剖面、步骤与窄屏职责截图。组件名称和职责可通过选择、聚焦、俯视和职责卡读取；19 组件的 AnswerService 及 Host 剖面仍有较密关系和连线交叉。窄屏无页面横向溢出，职责可读，但全景名牌较小，不声称完整空间图在手机上直接易读。

- 原有节点与事实依据复用，不为案例改渲染模板；把 CiteRAG 的 AnswerService / RAG 抽为独立子图，把 Iteroom 的 8 个剖面抽为职责子图。
- 固定实际取证 HEAD/dirty 和全部引用文件摘要；步骤保留教学前提、结构化来源及 assumed 状态。两项目各有一条实际读取调用源码支持的跨视图桥。
- 根统一场景通过 viewId 进入对应子图，route/focus 只引用该视图的节点。运行严格来源核验、完整 3D 生成以及子图独立 2D/3D 提取。
- 对完整增强图实际检查离线导航、父图/祖先返回、桥双向阅读、各场景前后步进、播放/暂停、手动暂停和窄屏职责；具体结果与截图保存在 enhanced 项目报告。

第一版功能断言之后，人工截图发现 CiteRAG 长面包屑在 375px 下遮挡职责卡顶部。补充手动进入、演示切图和模拟降级三个几何/点击回归，先复现旧实现失败；再按实际面包屑高度保留职责卡空间。功能断言通过与视觉验收分别记录，最终结果以追加复查报告为准。

修复后两个真实项目各追加 9 项检查通过，实际查看桌面与 375px 最终截图，标题/职责按钮不再被遮挡；内嵌模型和当前产物一致，外部 HTTP 请求、页面脚本错误均为 0。因交付图保留取证快照，后续源码变化必须重新核验。

**CiteRAG 最后观察**：图固定于 `2026-10-11T11:15:48Z` 的工作副本（北京时间 19:15:48），当时 335 条严格来源检查通过。`11:21:40Z` 严格复查时 README.md / runtime.py 又有外部修改，退出 2，报告 20 条 `SOURCE_HASH_MISMATCH`；`11:22:13Z` 最后观察仍有漂移。保留原图和 HTML，没有追随持续修改自动更新摘要。此图表达固定取证点，不能称其来源与当前仓库仍完全一致；最新观察见本地 `enhanced/citerag/current-strict-source-observation.json`。Iteroom 的 27 个取证文件、HEAD、clean 和 status 复查均一致。
